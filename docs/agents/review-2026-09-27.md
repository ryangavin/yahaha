# yahaha: Rust idiom and maintainability review

Scope: everything under `src/` (about 60k lines, 40% of it tests), read in full, excluding the vendored `rustysynth` and the Tauri mocks under `app/`. Nothing was modified. Clippy could not run: the crate is macOS-only (`mach2` and `coremidi-sys` refuse to build on Linux), so lint-class items below are by inspection. `cargo fmt --check` and grep-based counts did run.

Ranking is by importance: latent bugs first, then systemic type-safety gaps, then structure (single responsibility), then duplication, then tooling and hygiene. Each item names files and lines so it can be checked.

---

## Tier 1: latent bugs found in passing (small, worth fixing first)

### 1. Malformed SoundFont panics the control thread
`src/patches/sf2.rs:43` allocates `vec![0u8; size as usize - 4]` for a `LIST` chunk. A truncated or corrupt file with `size < 4` underflows: an overflow panic in debug, a capacity-overflow panic in release. The `- 4` seek two lines later has the same problem. Callers in `session/sound_set.rs` and `session/sound_library.rs` run on the control thread with no `catch_unwind` (styles do get one, `library.rs:348`). Fix: `size.checked_sub(4).context("bad LIST chunk")?` and reuse that value for the seek. The rest of this parser is careful, so this one slipped through the net.

### 2. A serialisation error would replace the user's sound library with an empty file
`src/patches/store.rs:88` `to_json()` returns `unwrap_or_default()`, and `save()` at `:103` writes that string through the tmp-and-rename path. On any serde error the atomic write faithfully installs an empty file. Return `Result<String>` (or `expect`, as `registration/mod.rs:347` does for the same case).

### 3. `Engine::retire` overflow path frees on the real-time thread
`src/engine/style_change.rs:29-34`: the comment says "dropping here would free on the real-time thread, so the oldest is handed back first", but the code does `rotate_left(1)` then `self.retired[3] = Some(style)`, which overwrites, and so drops, the oldest `Box<Prepared>`. It is a "cannot happen" path today. Return the evicted box to the caller, or `debug_assert!`, and at minimum fix the comment.

### 4. Audio buffers over 8192 frames leave the tail of the output unwritten
`src/synth.rs:1070` clamps `frames` to the 8192-sample scratch buffers, and the mix loop at `:1200` is `out.chunks_mut(channels).take(frames)`. Anything past that is never zeroed; cpal does not promise a cleared buffer. The offered sizes cap at 1024, so this only bites when the device default is used and is larger. Name the constant once (it is the literal `8192` at eight sites) and either fill the tail or render in chunks.

### 5. Extra-font slot bitmask aliases above 64 slots
`src/synth.rs:327-335` tracks "played" slots in a `u64` with `& 63`, while `Rack::with_fonts` (`synth/routing.rs:73`) allows 250 extras. Slot k and k+64 share a bit, so the idle-skip can silence a routed synthesizer. Cap extras at 63 with one shared constant, or use a per-slot `Vec<bool>` allocated up front.

### 6. Plugin host: poisoned mutexes and I/O under a lock reach the UI thread
`src/plugin/host.rs` and `editor.rs` have 24 `.lock().unwrap()` between them, while `plugin/sys.rs` consistently uses `unwrap_or_else(|e| e.into_inner())` and the rest of the crate does too (9 sites). A panic on a load thread poisons `LoadShared.state`, after which the UI thread's `progress()` poll panics. Also `host.rs:143-151` writes the scan cache to disk while holding that lock, and `editor.rs:180-212` leaks a retained view controller if the 2 s deadline passes before the completion block fires. One `lock()` helper in `plugin/mod.rs`, record after releasing the lock, and store a `Retained<NSViewController>` in the slot.

### 7. Blocking file and parse I/O under the session control mutex
The control loop (`src/session.rs:580-591`) takes the lock every 10 ms for LEDs and state publishing, and every client `send` takes it too. Under that lock the code saves JSON on every edit (`param_lock.rs:19`, `registration.rs:311-329`, `looper_banks.rs:105`, `sound_library.rs:389-408`, `sound_set.rs:99-114`, `settings.rs:56-64`, `plugins.rs:837`) and parses whole styles (`library.rs:151`) and pad files (`multipad.rs:113,152`). Plugins and SoundFont loads already go to worker threads; persistence and style loading should follow. One `Persist` worker plus reusing the existing `pending_style` mechanism covers it.

### 8. Part and channel indices are masked rather than validated, and inconsistently
`session/parts.rs:17` passes `SelectPart { part }` through unmasked to `Parts::select`, while its neighbours use `part & 3`. In `src/parts.rs` itself, `toggle`/`select`/`set_program` mask with `& 3` and `is_on`/`octave_of`/`volume`/`set_volume`/`hw_fader` index directly. So a client sending `part: 5` either silently edits Right 2 or panics, depending on the command. 34 such sites across `session/parts.rs`, `session/mixer.rs`, `session/plugins.rs`, `session/sound_library.rs`, `api/controllers.rs`; `knobs.rs` alone has 18 `(p & 3)` and five `.min(2)`. `multipad.rs:93-99` and `sounds.rs:169` do it right (return `CmdError`). A `Part`/`StylePart` enum or `TryFrom<u8>` newtype in the `*Cmd` types fixes it at the wire.

## Tier 2: systemic idiom gaps (type safety)

### 9. The domain's central values are bare integers with magic numerals
This is the single most pervasive maintainability issue.
- **Chord type** is a `u8`. `theory.rs:343-421,525-533` matches on `1 | 6`, `19..=27 | 29`, `30`, `31`; `fingering.rs:270-276` redeclares its own `MAJOR = 0, MINOR = 8, SEVENTH = 19 ...` (theory already exports two of them); `fingering.rs:412-423` and `ireal/chords.rs:33-176` are further tables of raw ids; `sff.rs:113` documents a `theory::ChordType` that does not exist. A `#[repr(u8)] enum ChordType` with `TryFrom<u8>` keeps `Copy`, packing and RT safety and makes every table reviewable.
- **Section slots** are `usize` with `4 + main`, `8 + i`, `13 + e` arithmetic at 15 sites (`engine/fills.rs`, `chart.rs`, `transport.rs`, `dynamics.rs`, `change_rules.rs`, `setup.rs`) plus `(8..=12).contains(&slot)` range tests, though `Prepared::slot_of` already centralises it. `usize::MAX` means "stop the band" in `Queued.slot` (11 sites). Pseudo source channels `STOP_ACMP_SRC = 255`, `UNISON_SRC = 254` are told apart by `src < 16`. `enum Next { Section(Slot), Stop }`, `enum Source { Pattern(u8), StopAcmp, Unison }`.
- **Time** is a bare `f64` in ticks with about 60 ad-hoc epsilons (`1e-6`, `1e-9`, and one `1.0` at `engine/chart.rs:352`) across 14 engine files; the "which boundary wins at the same tick" logic depends on them agreeing. A `Tick(f64)` newtype with one `EPS` and named comparisons, and `Ns(u64)` so nanoseconds and pad ticks stop being interchangeable.
- **Consts as enums**: `PATH_PLAIN/HARMONY/MULTI/FORWARD` matched with `_ => {}` (`live/pipeline.rs:120,267`), `R_LH/R_RH`, `KEY_HELD/KEY_RIGHT`, port tags with `slot.map_or(2, |s| 3 + s)` (`live.rs:1193`), fx bus indices `REVERB/CHORUS/VARIATION: usize` (`fx.rs:60`), pedal switches `SUSTAIN = 1, SOSTENUTO = 2, SOFT = 4` with `Effect::Switch(u8)` accepting any byte (`controllers.rs:73-78,301`).
- **Sentinels for None**: `UNSENT = 0xFF`, `HW_UNKNOWN = 255`, `NO_PARAM`, `NO_CC`, `NOT_LEARNING`, `NO_FX`, `NO_SOLO`, `NONE` (three separate definitions). Some are forced by atomics and deserve the "why not Option" comment that `NO_FX` has; others (`Takeover.hw`) are free to be `Option<u8>`.

### 10. Tuples, bool pairs and `Result`-as-`Either` where small structs belong
- 26 tuple-typed state fields in `session/` (`type Opened = (Library, Receiver<..>, usize, Box<Prepared>, Loaded)` at `library.rs:64`; `bank: Option<(usize, String, PathBuf, [String; PADS])>` at `multipad.rs:44`; `type Pending = (u8, String, Usage, u64)`), read as `p.2`, `b.3[i]`. `oracle.rs:557` `type Change = (u32, Score, Vec<(Ntt, Score)>)` and `Pair::transition()` returning `"M>m"` strings as map keys.
- `Cmd` in `live.rs:29-97`: `PartVolume(u8, u8)`, `StyleSend(u8, u8, u8)` with 255 as a sentinel, `Looper(bool)` meaning REC vs ON/OFF while the API already has `LooperRec`/`LooperOnOff`.
- `sff.rs:1024` `Vec<(u32, Result<SectionId, String>)>` where `Err` is a perfectly valid opaque marker.
- `Strum { active, started }` is a three-state machine as two bools (`live/kbdfx.rs:392`). Ten functions take two or more positional bools (`harmony.rs:314,343`, `session/leds.rs:26`, `session/sound_library.rs:835`).
- `Button` mixes toggle and set variants (`Acmp`/`SetAcmp`, `Unison`/`SetUnison` ...); `enum Switch { Toggle, Set(bool) }` halves the arms.

### 11. The synth ring's sentinel-byte protocol is spread over four modules with two conventions
Non-MIDI messages ride the `[u8; 3]` ring by first byte: `CLICK = 0xF9` (`click.rs:12`), `ROUTE_BANK = 0xFD`, `AUDITION = 0xF4` (`patches/route.rs:214,219`), `MONO = 0x70` (`synth/xg_part.rs:21`), drum messages `0x40..=0x62` (`synth/drum_setup.rs:62`). `drum_setup.rs` documents "below 80H, which no MIDI message starts with", while the others reuse real System Common/Realtime status bytes. The consumer is an order-dependent `if ... continue` chain (`synth.rs:996-1057`) and nothing asserts disjointness. One `enum SynthMsg` with a `decode` in one module and a `const _: () = assert!` on the ranges.

### 12. Two error currencies in the session layer, and a `fail()` footgun
`Control::fail` (`session.rs:362`) returns `Result<(), CmdError>`, so callers needing another `T` write `Err(self.fail(..).unwrap_err())` (five sites, plus a `sl_fail` wrapper). Registrables and plugin code use `Result<_, String>` (35 signatures), so `registration/sections.rs` has 14 `map_err(|e| e.to_string())` and every `plugins_cmd`/`sounds_cmd` arm converts back. Make `fail` generic, give registrables `CmdError` or a newtype with `From`. Elsewhere `anyhow` with downcastable typed errors (`StatusError`, `LoadTimedOut`) is used well.

## Tier 4: duplication

### 16. Copy-pasted helpers, counted
- **Bar length**: `bar_ns` defined 11 times as a fn or closure; the expression `60e9 / bpm * (tpb / ppq)` appears 55 times across `src` and `tests/`. One `Prepared::bar_ns()`.
- **Corpus test loader**: the `corpus/MOX_v2/SlowWalker.T552.sty` path plus `if !exists { return }` in 46 files; `fn offline()` defined 6 times and `session()`/`engine()`/`prep()` fixtures in about a dozen more; "corpus missing; skipping" 107 times. Without the corpus, dozens of tests are green with zero assertions. One `testkit` module and `#[ignore]` or a feature gate rather than a silent early return.
- **Atomic JSON write**: six implementations (`registration/mod.rs:490`, `patches/store.rs:101`, `plugin/presets.rs:238`, `plugin/scan.rs:186`, `session/sound_set.rs:99`, `session/plugins.rs:1055`); only `scan.rs` is safe against two writers, and `session/settings.rs:56` is a plain `fs::write` that swallows errors.
- **SMF plumbing**: `be32`, MThd/MTrk header parsing, and tempo/time-signature meta decoding duplicated between `sff.rs` and `multipad/file.rs`; an SMF writer exists three times (`multipad/file.rs:398`, `multipad/synthetic.rs:93`, `capture.rs:408`) plus per-test copies.
- **LED state machines**: `section_leds` (`launchkey.rs:745-802`) and `section_looks` (`:951-1005`) encode the same branching once for palette LEDs and once for RGB looks; same for `regist_leds`/`regist_looks`. The banner at `:884` says one look model should drive both, and pages 2 and 3 already do. A recent change (`landing`) had to be made twice; nothing checks they agree.
- **Knob tables**: `KnobFn::id/short/name` are three 20-arm matches with six embedded part-name arrays while `parts::NAMES` exists; `Knobs::turn`/`reset` repeat the reverb/chorus/delay triples with magic `part_fx[..][1..3]` indices.
- **MIDI bytes**: `0xB0 | ch`, `0x90 | ch`, `0xE0 | ch` built by hand at 66 sites in `engine/` and 21 more elsewhere; status parsing `m[0] & 0xF0 == 0xB0` repeated in `mirror.rs`, `setup.rs` (twice), `prepared.rs`, `multipad.rs`. A tiny `midi::msg` module.
- **Note-group loops**: three copies of "collect simultaneous note-ons into `keys: [u8; 8]`" (`engine/playback.rs:112`, `chords.rs:166`, `chords.rs:218`), already subtly divergent.
- **Ring handoff pairs**: the "new in, old back out" `Producer`/`Consumer` pair appears five times (`live.rs:1231,1662`, `synth.rs:136`). A `Handoff<T>` type.
- **Hand-mirrored enums** between `api` and `engine`: 44 match arms in `session/harmony_arp.rs`, `looper.rs`, `multipad.rs`, while other engine enums are serialised directly. Pick one boundary policy; where mirrors stay, use `From` impls.
- **Enum stepping**: three `step(self, d: i8)` implementations with clamp, saturate and wrap (`knobs.rs:57`, `launchkey.rs:277`, `parts.rs:97`).
- **CLI arg loops**: `main.rs`, `capture.rs:1160`, `bench.rs:334`, `plugin/cli.rs` each hand-roll `while let Some(flag) = it.next()`.

## Tier 5: tooling and hygiene

### 17. Formatting is not enforced
`cargo fmt --check` reports 4086 diff hunks; effectively no file is formatted. 823 lines exceed 120 columns and the longest is 1605 characters. There is no `rustfmt.toml`. Whatever width the owner prefers, one `cargo fmt` commit plus a check in the verify gate ends this.

### 18. No `[lints]` table; clippy is a convention in a doc, not a gate
`docs/handoff.md:57` already notes "clippy drift". `Cargo.toml` has no `[lints]`. Worth enabling: `clippy::undocumented_unsafe_blocks` (108 `unsafe` sites; `rt.rs` has 16 with zero `SAFETY:` comments, `midi.rs` 19 with two, `plugin/sys.rs` 33 with three), `clippy::cast_possible_truncation` as warn (301 `as u8`, 684 `as usize`; most are guarded, the unguarded ones are listed in the per-area notes), `clippy::too_many_lines`.

### 19. Test placement is inconsistent and inflates file sizes
`sim.rs` is 3169 lines of which 2602 are seven inline test modules, plus three more via `#[path]`; `live.rs` is 48% tests; `session/fx.rs`, `session/style_change.rs` (whose tests are OTS-Link tests) and `session/controllers.rs` carry 350 to 480 line inline modules, while `engine/*_tests.rs` and `session/*_tests.rs` use the extracted convention. Pick the extracted one.

### 20. Smaller items
- `api.rs:116-129`: the `AppCmd` deserialiser dispatches on serde's error text (`starts_with("unknown variant")`), so a nested enum with an unknown variant falls through to the wrong error. Read the tag once and dispatch on it.
- Hard-coded `~/Library/Application Support/yahaha` in the library crate (`session/settings.rs:41`, `session/plugins.rs:100`) ignores `Options::data_dir`, so tests and the `state-json` tool can write to the real profile.
- `midi::init()` (`midi.rs:151-173`) swallows thread-spawn and `MIDIClientCreate` failures. `rt::Wakeup` is `Copy` over a Mach semaphore with no `Drop` and the create status discarded.
- `synth.rs:1297` and `plugin/cli.rs:473` both special-case a device name (`"Model 16"`) for the output pair.
- `ui.rs:293-295` leaves raw mode on if the second setup call fails, and a panic in `draw` leaves the terminal unrestored; an RAII guard or panic hook.
- `Inner::publish` (`session.rs:530-575`) rebuilds and deep-compares the whole `AppState` every 10 ms under the lock, and `sounds_touch` hashes by JSON-serialising.
- Stale attributes: `#[allow(dead_code)]` on `is_running` (29 callers) and `Msgs::iter` (used in non-test code); `channel_plugin` is a pure alias of `channel_plugin_state`.
- Drifted doc comments: `session.rs:863`, `synth.rs:495,1225`, `synth/routing.rs:103`, `engine/playback.rs:237`, and `sff.rs:608` documents a fallback the function does not perform.
- `lib.rs:59,78` duplicate the alternate note-name table; `parse_chord` and `parse_note` each implement lookup.
- `main.rs:26,28` index `args[2]`/`args[3]` and panic on `yahaha screen` with no arguments; `main.rs:12` has a match guard that covers an impossible alternative.

## Strengths to preserve

- **Real-time discipline is real and tested.** Fixed arrays, `rtrb` rings, atomics, boxes handed back to the control side to free, one production `unwrap` in six thousand lines of RT code, and counting-allocator tests per thread in `tests/*_no_alloc.rs`. `synth/stream.rs`'s `CoreSlot` and `route.rs`'s packed CAS table are model modules.
- **Determinism by design.** Time is always a `now` parameter and output always goes through the `Sink` trait, so the whole engine, and via `session/offline.rs` the whole session, runs offline against real style files. This is why the test count is high and hardware-free.
- **Static extension points.** `engine/hooks.rs` with a fixed, documented, test-pinned call order and one field per feature in `Features`; the `impl Control` per-feature convention wired in three fixed places; the `Registrable` table with per-feature `Option`-field serde structs. Table-driven designs come with tests that pin the tables (`controllers::FUNCTIONS`, `megavoice::VOICES`, `launchkey::every_page_covers_the_pads_in_order`).
- **Parsing robustness culture.** `sff::Reader` never indexes unchecked, byte-flip fuzz tests exist for styles and pad files, `theory::plays` uses `checked_shr`; only the SF2 chunk in finding 1 escaped.
- **Serde compatibility and typed anyhow errors.** Tagged enums, unknown groups round-tripped, version refusal instead of half-reads, downcastable errors with retry decided on the type rather than the message.
- **Documentation density.** Module headers state the model, the thread ownership, the manual page references and the decisions made where the manuals are silent. Test names are behaviour sentences.

## Suggested order of attack
1. Tier 1 items 1 to 6: each is a few lines.
2. Finding 8 and the `Part` enum, which also removes most of the `& 3` and `.min(2)` masking in finding 9.
3. `cargo fmt` once, add `rustfmt.toml` and a `[lints]` table, and put `fmt --check` in the verify gate (17, 18).
4. `testkit` module and extracted test files (16, 19).
5. Persistence worker plus one `write_atomic` (7, 16).
6. Group the flat `Control` and `Shared` fields; `Default` for `Snapshot`; split `process`, `step`, `revoice_part`, `import` (13, 14).
7. `ChordType`, `Slot`, `Tick` newtypes and the `SynthMsg` enum as time allows (9, 11).
